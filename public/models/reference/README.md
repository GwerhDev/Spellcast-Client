# Reference models (TCORE-124)

These two `.glb` files are a **1:1 export of the current runtime geometry** — the same corner
plate and medallion mesh `CoverFrameMesh.tsx` builds by extruding `public/frames/grimoire-corner.svg`
and `public/frames/grimoire-medallion.svg` at runtime, exported once as static geometry.

They exist as a **reference for whoever models the real, final pieces in Blender** — so the
proportions, bevel depth, and relative size/position of the gem vs. the bronze plate don't
have to be guessed from the flat 2D SVGs alone. They are NOT meant to ship as the final
in-app assets.

## Contents

- `grimoire-corner-reference.glb` — the corner plate, single mesh named `CornerPlate`,
  unmirrored (the app mirrors it into all 4 corners via code, so only one canonical
  orientation is exported). Origin at the mesh's own center (via `Geometry.center()`).
- `grimoire-medallion-reference.glb` — a `Medallion` group containing two separate meshes:
  `MedallionPlate` (the bronze frame) and `Gem` (a small icosahedron standing in for the
  turquoise stone, positioned slightly in front of the plate on +Z).

## What to keep from these when modeling the real pieces

- **Corner**: 64×64 source proportions (from the SVG's own viewBox), extrude depth ~6 units
  relative to a ~28px on-screen footprint, small bevel on all edges.
- **Medallion**: 32×26 source proportions, gem radius ≈ 1/8 of the medallion's own width,
  gem sitting slightly proud of the plate's front face (not flush).
- **Materials in these files are placeholders** (flat `meshStandardMaterial`/
  `meshPhysicalMaterial`, no textures) — not meant to be kept, just a starting silhouette/
  proportions reference.

## Regenerating

Generated by reconstructing `CoverFrameMesh.tsx`'s own geometry-building code in a headless
browser session and exporting via `three-stdlib`'s `GLTFExporter` — not from a checked-in
script (one-off tooling). If the runtime geometry changes and this reference needs updating,
ask Claude to regenerate it the same way, or export directly from a running dev session using
`GLTFExporter.parse(mesh, cb, { binary: true })` against the same mesh-building logic in
`CoverFrameMesh.tsx`.
